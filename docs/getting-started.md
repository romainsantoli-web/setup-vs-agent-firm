## What is Firm Ecosystem?

Firm Ecosystem is the **inter-session memory layer for AI agents**. It solves the #1 problem
with AI coding assistants: **they forget everything between sessions.**

With Firm, your agents:
- **Remember** what worked (and what didn't) across sessions
- **Learn** patterns through Hebbian weight reinforcement
- **Communicate** via A2A Protocol and 138 MCP tools
- **Self-audit** security configs before deployment

## Prerequisites

- Python 3.11+
- VS Code, Cursor, Windsurf, or Claude Code
- 5 minutes

## Step 1: Install firm-cli

```bash
pip install firm-cli
firm --version
# firm-cli 1.0.0
```

## Step 2: Create your first agent firm

```bash
firm init --sector fintech --size startup --output ./my-firm
```

This generates a complete agent firm with:
- 4 department agents (Engineering, Risk, Compliance, Growth)
- `CLAUDE.md` with Layer 2 memory seeds
- `AGENTS.md` hierarchy + orchestration protocol
- MCP server config + security defaults
- Sector-specific skills (AML/KYC for fintech)

```
my-firm/
├── AGENTS.md                    # Agent hierarchy
├── CLAUDE.md                    # Hebbian memory (Layer 1-4)
├── CONTRIBUTING.md              # Contribution guidelines
├── mcp-config.json              # MCP server configuration
├── .vscode/settings.json        # VS Code MCP integration
├── .github/
│   ├── agents/
│   │   ├── firm-ceo.agent.md    # CEO orchestrator
│   │   ├── department-engineering.agent.md
│   │   ├── department-risk.agent.md
│   │   ├── department-compliance.agent.md
│   │   └── department-growth.agent.md
│   └── prompts/
│       └── firm-delivery.prompt.md
└── scripts/
    └── install-skills.sh
```

## Step 3: Start the MCP server

```bash
cd my-firm
firm start
# MCP server listening on http://127.0.0.1:8012
# 138 tools available
```

## Step 4: Connect VS Code

Add to your `.vscode/settings.json` (already generated by `firm init`):

```json
{
  "mcp.servers": {
    "firm": {
      "url": "http://127.0.0.1:8012/mcp"
    }
  }
}
```

That's it. Your AI agent now has access to:
- **8 Hebbian memory tools** — learn patterns, track drift, weigh rules
- **47 security checks** — audit configs before deployment
- **8 A2A tools** — communicate between agents
- **6 fleet tools** — manage multiple Gateway instances

## Step 6: Export & share memory

```bash
# Export your firm's learned patterns
firm memory export --output team-memory.json

# Import into another project (merge mode — deduplicate rules)
cd /other/project
firm memory import team-memory.json --merge
```

This enables **memory transfer between projects** — your agents carry their knowledge with them.

## Next Steps

### Use the Python SDK

```bash
pip install firm-sdk
```

```python
from firm_sdk import FirmClient

client = FirmClient()
status = client.memory_status()
result = client.security_scan(config_path="./config.yaml")
```

### Run security audit

```bash
# Via CLI
firm start  # ensure server is running

# Via Python SDK
from firm_sdk import FirmClient
client = FirmClient()
scan = client.security_scan()
print(f"Findings: {scan.data['finding_count']}")
```

### Deploy to production

```bash
# Docker Compose
docker compose up -d

# Kubernetes (Helm)
helm install firm deploy/helm/firm-ecosystem

# AWS ECS Fargate (Terraform)
cd deploy/terraform && terraform apply
```

## Hebbian Memory in 30 Seconds

Firm implements **4-layer adaptive memory** inspired by neuroscience:

| Layer | Purpose | Volatility |
|-------|---------|-----------|
| Layer 4: Meta Instructions | Highest authority, rarely changes | Very low |
| Layer 3: Episodic Index | Session summaries, auto-decayed | High |
| Layer 2: Consolidated Patterns | Learned rules, Hebbian-weighted | Medium |
| Layer 1: Core Identity | Immutable project DNA | None |

**Weight formula:** `new = old + lr × activation - decay × (1 - activation)`

Frequently used patterns gain weight. Unused patterns decay and eventually get pruned.
This means your agents **learn from repetition** — just like real neurons.
